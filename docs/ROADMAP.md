## Implementation milestones (revised order)

1. **Backend foundation** — ✅ **Done.** FastAPI skeleton, Postgres/SQLite-compatible schema from `DATA_MODEL.md`, config/env setup, `/api/health`. 3 tests passing.
2. **Data simulator** — ✅ **Done.** Deterministic telemetry generator (`app/ingestion/telemetry_simulator.py`) producing multi-week realistic electricity/water patterns; 6 named scenarios (`app/ingestion/scenarios.py`); CSV upload (`app/ingestion/csv_source.py`) sharing the same normalized-measurement contract and service layer as the simulator; `/api/data/upload`, `/api/data/simulate`, `/api/measurements`, `/api/locations`, `/api/resources`; `python -m app.cli seed-demo` CLI. 40 tests passing (37 new + 3 carried over from Milestone 1).
3. **Anomaly engine** — ✅ **Done.** Causal baseline engine (contextual, cold-start-aware), safe deviation/z-score calculation, persistence detection, a documented point-based severity/classification system, evidence generation, deterministic candidate causes, and factor-driven cost/CO2e calculations (`app/analytics/`). Persisted via `app/services/analytics_service.py`; exposed via `POST /api/analysis/run`, `GET /api/anomalies`, `GET /api/anomalies/{id}`, `GET/PUT /api/config/factors/...`. Verified end-to-end against the real Greenfield Public School dataset — the injected water leak is independently discovered and classified `operationally_suspicious`, and the legitimate-spike scenario is confirmed to never be. 93 tests passing (56 new). No AI, no frontend — per this milestone's explicit scope.
4. **AI investigation** — ✅ **Done.** Structured evidence-packet builder (`app/ai/evidence_packet.py`), strict Pydantic output schema with observed/inference separation and categorical `reasoning_confidence` (`app/ai/schemas.py`), a dedicated system+user prompt (`app/ai/prompts.py`), the real Anthropic client wrapper (`app/ai/client.py`), two-layer validation — schema then grounding (`app/ai/grounding.py`) — and a deterministic fallback engine held to the identical grounding standard (`app/ai/fallback.py`), orchestrated by `app/ai/investigation_service.py` and exposed via `POST /api/anomalies/{id}/investigate`. Verified end-to-end against the real Greenfield Public School water-leak anomaly with no API key configured (`python -m app.cli investigate-demo`) — correctly falls back and produces a complete, evidence-grounded investigation. 130 tests passing (37 new), all AI-path tests using a mocked provider so the suite needs no real API key. No frontend, no intervention workflow — per this milestone's explicit scope.
5. **Frontend** — ✅ **Done.** Five-page React app (Overview, Resources, Investigations, Impact, Data) per `ARCHITECTURE.md`, consuming the backend end-to-end with no duplicated business logic. Restrained enterprise styling per the brief (no gradients/neon/glassmorphism), a hand-rolled SVG chart component instead of a charting library dependency, and an honest AI-vs-fallback disclosure on every investigation. Two small backend read-only additions were made to avoid the frontend reconstructing backend logic (`GET /resources/{id}/baselines`, `evidence` on the anomaly detail response). Full manual integration walkthrough (seed → analyze → investigate → recommend → intervene → complete → verify → view impact → Run Demo) verified against real running servers — see the Milestone 6 completion report. 20 frontend tests passing (component + integration, mocked backend) plus all 167 backend tests still passing.
6. **Intervention + verification** — ✅ **Done.** Recommendation generation tied to investigation completion (`app/services/recommendation_service.py`), intervention lifecycle separate from verification outcome (`app/services/intervention_service.py`, revised `Intervention` model), deterministic verification reusing the Milestone 3 baseline engine with a dedicated counterfactual comparison for avoided-consumption (`app/services/verification_service.py`), factor snapshotting on every `ImpactRecord`, and a full idempotent backend demo workflow (`app/services/demo_service.py`, `POST /api/demo/run`, `python -m app.cli run-demo`). Verified end-to-end against the real Greenfield Public School dataset — reaches `VERIFIED` with real avoided-consumption/cost/CO2e figures; a deliberately dishonest early completion correctly produces `no_measurable_improvement` instead. 165 tests passing (35 new), including adversarial numerical-integrity tests. No frontend yet — per this milestone's explicit scope.
7. **Demo mode UI** — ✅ **Done.** Run EcoTwin Demo button (Milestone 6) plus, from Milestone 7: a richer completion summary (deviation, duration, building status, occupancy), an honest step list during the single backend call, a scoped `Reset Demo` control (`POST /api/demo/reset`), an investigation timeline, a deterministic-vs-AI methodology split, and a real-telemetry before/after chart on the investigation detail page — all presentational, no new backend business logic. Manually verified 3x against real running servers: fresh seed → idempotent re-run → reset → fresh run again, each producing the identical deterministic story with new IDs after reset. 174 backend + 31 frontend tests passing.
8. **Testing / hardening** — ✅ **Done.** Adversarial data tests (empty dataset, single measurement, missing occupancy/operating status, zero/tiny/huge consumption, duplicate/out-of-order timestamps, negative-consumption rejection), adversarial AI grounding tests (invented percentages, causes, evidence signals, savings claims, false "verified" claims — all confirmed rejected), intervention/verification edge cases, and database integrity checks (`tests/hardening/`). Security audit (no secrets committed, CORS scoped, API key never reaches the frontend bundle — confirmed by grepping the built bundle), dependency audit (every dependency justified, none unused), and a documentation consistency pass (found and fixed several stale cross-references, including a hardcoded local path in a Milestone 3 test that would have broken reproducibility elsewhere). Four real bugs found and fixed this milestone alone — see `TECHNICAL_DEBT.md`. 203 backend + 36 frontend tests passing (239 total). See `HACKATHON_READINESS.md` for the full audit and honest scorecard.
9. **Deployment** — Vercel (frontend) + Render/Railway (backend) + managed Postgres, per `DEPLOYMENT.md`; verify the fallback path also works in the deployed environment (AI key removed test).
10. **Documentation pass** — update every doc to match what was actually built, note any deviations from this plan and why.

After each milestone: run tests, fix errors, explain what was implemented, update the relevant doc, note remaining issues — no big-bang implementation step.
